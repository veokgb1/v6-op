# 必须做与不能做

## 1. 本讨论区必须做

### 1.1 清理第一阶段真实状态

必须回答：

- 第一阶段真实完成了什么？
- 哪些只是结构跑通，不代表稳定可用？
- 哪些历史签收结论需要重新解释？
- 哪些风险来自实现，哪些风险来自原始大纲解释不清？

### 1.2 梳理用户需求

必须整理：

- 用户现在最困惑的地方。
- 页面哪些词不清楚。
- 哪些结果无法解释。
- 哪些操作让用户不敢继续。
- 用户希望系统如何解释复杂筛选。

### 1.3 建立问题归类框架

至少包含：

- 来源层。
- 网络取数层。
- 本地保存/缓存层。
- 技能层。
- 路径层。
- 报告/解释层。
- 前端体验层。
- 管理功能层。

### 1.4 建立第二阶段开发方法

必须形成：

- 第二阶段开发宗旨。
- 第二阶段边界。
- 第二阶段优先级。
- 哪些先做，哪些后做。
- 哪些需要多人审，哪些可以单人实现。

## 2. 本讨论区不能做

### 2.1 不做代码实现

本区不写业务代码。

不直接修改：

- `web/app.js`
- `scripts/execution_engine.py`
- `scripts/source_resolver.py`
- `scripts/producers/*`
- 其他运行代码

### 2.2 不下达施工命令

除非人类明确要求，否则不生成正式 commands 文件。

### 2.3 不把猜测当事实

不允许：

- 没看代码就说“当前代码已经怎样”。
- 没看运行结果就说“这个问题已经修好”。
- 没看报告就说“报告里有/没有”。

### 2.4 不继续扩大范围

本讨论区当前不做：

- 灰色技能大规模接入。
- 打分制实现。
- 抗压模型实现。
- 完整 DAG 编辑器。
- 直接重写执行引擎。
- 直接做前端大重构。

这些可以讨论，但不能在本区直接变成施工任务。

## 3. 当前阶段目标

最终要形成三类正式产物：

1. 第一阶段清理结论。
2. 第二阶段开发纲要宗旨。
3. 第二阶段开发计划。

在这些产物形成前，不进入大规模实现。
