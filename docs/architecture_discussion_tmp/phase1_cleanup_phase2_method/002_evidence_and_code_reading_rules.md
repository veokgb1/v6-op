# 证据与代码阅读规则

## 1. 总规则

不能凭空无据地做当前系统判断。

凡是涉及当前 V6OP 代码、当前页面、当前执行链路、当前报告、当前缓存、当前取数逻辑的判断，必须先看代码或运行产物。

如果没有看代码，必须明确写：

```text
本判断未基于代码阅读，只是概念推断。
```

## 2. 证据分类

每条重要判断必须归入以下之一：

| 类型 | 含义 |
|---|---|
| 代码证据 | 实际打开代码文件看到的实现事实 |
| 文档证据 | 来自章程、031、032、030、历史报告 |
| 运行证据 | 来自 execution_result、run_report、日志、截图 |
| 人类需求 | 人类明确提出的使用痛点或目标 |
| 推断 | 基于上述证据的架构判断 |
| 待验证 | 尚未读代码或尚未运行验证 |

## 3. 必须看代码的情况

以下问题必须先看代码：

- 问财到底在 source 还是 producer。
- K线是否真的访问 baostock / akshare / yfinance。
- 缓存是否读写成功。
- 参数是否真的传到 producer。
- 三路径到底如何组合。
- 报告字段从哪里生成。
- 前端页面是否真的过重。
- 某个按钮是否真的有后端接口。
- 中止、续跑、清缓存、历史报告是否真实存在。

## 4. 可以不看代码的情况

以下问题可以先做概念讨论：

- 通用技术方法论。
- 用户体验语言如何更容易理解。
- 股票策略概念本身。
- 第二阶段愿景。
- 还没有要求落地到当前代码的纯架构假设。

即使如此，也必须标注：

```text
这是概念讨论，尚未映射到当前代码。
```

## 5. 代码阅读记录格式

Claude 分析师或 Codex 架构师如果说“我看了代码”，必须写出：

```text
已阅读：
- F:\v.6\v6-op\scripts\source_resolver.py
  观察：问财由 resolve() 调 wencai_source.run() 生成 scope_codes。

- F:\v.6\v6-op\scripts\execution_engine.py
  观察：当前 producer 映射中没有 wencai；三路径存在手写分支。
```

禁止：

```text
我看了代码，整体是这样的……
```

这种说法不算代码证据。
