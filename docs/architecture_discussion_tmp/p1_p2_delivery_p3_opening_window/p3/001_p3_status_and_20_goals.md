# P3 当前状态与 20 个候选大目标

> 本文件用途：开启新的 P3 阶段讨论。  
> 注意：这里的 P3 是 P1/P2 交付后的新第三阶段，不是旧开发流水中的 `V6OP-004 phase3_single_page_console`。

---

## 1. P3 当前完成情况

```text
P3 尚未正式开发。
```

但 P3 的基础条件已经具备：

1. P1 已有可运行骨架。
2. P2 已有五层解释、数据血缘、Bridge、管理中心、G8 表达式收口。
3. 自动测试通过：`568 passed，0 failed`。
4. 真实浏览器 smoke 通过：`pass，9/9`。
5. 问财接口 smoke 通过：`status=ok，api_called=true`。

所以 P3 不是从零开始，而是从“可信可解释的操盘台”进入“更有决策价值的操盘系统”。

---

## 2. P3 总宗旨建议

```text
让系统不只告诉用户“发生了什么”，还要帮助用户判断“值不值得继续看、怎么比较、什么时候复查、风险在哪里”。
```

P1 解决能跑。

P2 解决可信、透明、可解释。

P3 应该解决：

```text
筛选质量、比较排序、风险抗压、复查跟踪、策略运营化。
```

---

## 3. P3 候选 20 个大目标

### 1. 真实大任务验收中心

当前情况：

```text
P2 做了真实浏览器 smoke 和小问财 smoke，但没有把全A 5000、问财大返回、冷缓存/热缓存做成固定验收中心。
```

P3 要做：

```text
建立真实任务验收中心，覆盖全A 5000、问财 0、问财少量、问财接近上限、冷缓存、热缓存、断网/接口失败。
```

验收：

```text
每个场景有固定脚本、固定报告、耗时、失败率、命中数、数据血缘。
```

### 2. 综合评分与排序引擎

当前情况：

```text
系统能给出命中股票，但还没有统一分数和排序。
```

P3 要做：

```text
建立综合评分：技能命中分、风险扣分、数据可信度、板块/资金/趋势加权。
```

验收：

```text
命中列表不再只是代码列表，而是按综合分排序，并解释每只股票为什么排在这里。
```

### 3. 抗压模型与风险体检

当前情况：

```text
排雷技能存在，但不是完整抗压模型。
```

P3 要做：

```text
建立抗压模型：跌幅、波动、流动性、财务雷、公告雷、板块退潮、指数环境。
```

验收：

```text
每只候选股有风险等级、主要风险因子、是否建议继续观察。
```

### 4. 候选股生命周期管理

当前情况：

```text
历史报告能恢复参数，但候选股没有生命周期。
```

P3 要做：

```text
候选股进入“新发现 / 观察中 / 已放弃 / 已过期 / 已复查”状态流。
```

验收：

```text
用户能看到一只股票什么时候被发现、为什么入池、后续复查结果如何。
```

### 5. 观察清单与复查机制

当前情况：

```text
系统能跑一轮，但没有持续观察清单。
```

P3 要做：

```text
建立 watchlist，支持加入观察、到期复查、每天/每周重新跑指定清单。
```

验收：

```text
观察清单能触发复查，并显示信号增强、减弱、失效。
```

### 6. 多轮运行对比

当前情况：

```text
历史运行能列出来，但不能做多轮对比。
```

P3 要做：

```text
比较两次或多次运行：新增、消失、连续命中、分数变化、风险变化。
```

验收：

```text
用户能知道哪些票是连续出现，哪些票是今天突然出现，哪些票已经失效。
```

### 7. 历史回放与防未来函数

当前情况：

```text
系统主要跑当前数据，没有正式历史回放模式。
```

P3 要做：

```text
按历史日期回放：只使用当日以前数据，检查当时是否会命中。
```

验收：

```text
报告明确 as_of_date，避免未来数据污染。
```

### 8. 参数敏感性分析

当前情况：

```text
用户能调参数，但不知道参数变化对结果影响多大。
```

P3 要做：

```text
同一策略自动跑多组 days、signal_bars、strict/soft，输出敏感性矩阵。
```

验收：

```text
系统告诉用户：这个结果是稳定命中，还是参数稍变就消失。
```

### 9. 策略预设库治理

当前情况：

```text
有 P1-P6 和收藏，但还不是治理过的策略资产。
```

P3 要做：

```text
预设版本化、分类、说明、适用市场、默认参数、风险提示、历史表现。
```

验收：

```text
每个预设都像一个可管理策略，而不是普通文本收藏。
```

### 10. 板块与市场环境层

当前情况：

```text
有板块联动，但没有完整市场环境判断。
```

P3 要做：

```text
加入指数趋势、市场宽度、板块强弱、题材持续性、成交额环境。
```

验收：

```text
报告能说明本轮候选股处于什么市场环境，不只看个股。
```

### 11. Bridge Capability v2

当前情况：

```text
P2 完成问财 Bridge constrained / annotate。
```

P3 要做：

```text
把公告、财务、资金、概念、新闻、东方财富/同花顺等外部能力纳入 Bridge 契约。
```

验收：

```text
Bridge 不只是问财，而是一类外部验证能力。
```

### 12. Provider 管理中心

当前情况：

```text
P2 有数据血缘，但 provider 管理还比较基础。
```

P3 要做：

```text
展示 baostock / akshare / yfinance / 问财 / 未来东方财富等 provider 的可用性、失败率、延迟、最近成功时间。
```

验收：

```text
用户不用猜本轮数据来自哪里、哪个源坏了。
```

### 13. 长任务队列与续跑

当前情况：

```text
有 abort 和运行状态，但没有正式队列。
```

P3 要做：

```text
支持长任务排队、暂停、续跑、失败重试、断点恢复。
```

验收：

```text
全A 5000 这类长任务不再像一次性脚本，而是可管理任务。
```

### 14. 报告工作台

当前情况：

```text
报告是 JSON/Markdown 和页面展示，尚未形成工作台。
```

P3 要做：

```text
报告筛选、搜索、对比、导出、日报生成、重点候选解释。
```

验收：

```text
用户能在历史报告中快速找到有用结果。
```

### 15. 用户动作建议层

当前情况：

```text
P2 能解释为什么为 0，但还没系统化建议下一步动作。
```

P3 要做：

```text
根据归零层、分数、风险、数据质量，建议放宽参数、换路径、换来源、补数据、复查某清单。
```

验收：

```text
报告不只解释，还给可执行下一步。
```

### 16. 数据质量异常检测

当前情况：

```text
P2 标注了 failed/stale/degraded，但异常检测还不完整。
```

P3 要做：

```text
检测停牌、缺口、复权异常、成交量异常、日期断层、缓存污染、重复代码。
```

验收：

```text
异常数据不会静默进入结论。
```

### 17. 性能与缓存工程化

当前情况：

```text
P2 已有三层缓存，但还没有专门性能治理。
```

P3 要做：

```text
缓存索引、清理策略、空间占用、并发取数、批量运行耗时预算。
```

验收：

```text
大任务有明确耗时和资源预算，不再靠感觉。
```

### 18. 安全与密钥治理

当前情况：

```text
P1/P2 已避免泄露 key，但还没有完整密钥治理。
```

P3 要做：

```text
.env 管理、日志脱敏、报告脱敏、provider credential 状态、异常时不输出秘密值。
```

验收：

```text
所有报告和日志都不泄露密钥。
```

### 19. 前端体验专业化

当前情况：

```text
主操盘台已经可用，但 P3 需要更高密度、更稳定、更少混乱。
```

P3 要做：

```text
主操盘台、管理中心、报告工作台、观察清单的清晰导航；减少堆叠；移动端/宽屏验收。
```

验收：

```text
用户不用理解代码结构，也能稳定完成日常操盘流程。
```

### 20. P3 验收与交付体系

当前情况：

```text
P2 已经形成命令、报告、浏览器 smoke、签收报告。
```

P3 要做：

```text
从一开始建立 P3 大纲、开发命令、验收矩阵、浏览器验收、真实任务验收、签收报告。
```

验收：

```text
P3 不再出现“做了很多但不知道是否完成”的情况。
```
