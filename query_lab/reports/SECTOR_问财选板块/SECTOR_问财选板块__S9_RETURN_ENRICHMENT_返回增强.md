## 核心问题答案

### 1. 上涨原因能不能返回？

**不能。**

| 问法 | 结果 | 结论 |
|------|------|------|
| 今日涨幅排名前10的板块，**上涨原因是什么** | empty_result | "上涨原因是什么" 关键词触发 pywencai 解析失败，整条 query 返回空 |
| 今日涨停家数排名前10的板块，**原因是什么** | rc=7 sector_with_index_fields | "原因是什么" 被忽略，返回普通板块列表；无原因列 |
| 今日主力净流入排名前10的板块，**资金流入原因是什么** | rc=8 sector_with_index_fields | "资金流入原因是什么" 被忽略；无原因列 |

**结论**：
- `上涨原因是什么` → **KILLS THE QUERY**（返回空）。严禁自动生成。
- `原因是什么` / `资金流入原因是什么` → **reason_query_ignored**，pywencai 忽略原因追问，仍返回板块列表，无 raw_column 包含原因文本。
- 任何"原因类"追问不能让 sector 返回文字说明。

### 2. 板块指数代码/指数简称/指数行情字段能不能返回？

**可以，且是默认行为。**

zhishu backend 返回的每一行都包含：

| 字段 | 含义 | 示例 |
|------|------|------|
| `指数代码` | 板块/行业/概念指数代码（88xxxx/884xxx） | 884263.TI |
| `指数简称` | 板块名称（中文） | 通信线缆及配套 |
| `指数@涨跌幅:前复权[日期]` | 当日涨跌幅 | 6.9104 |
| `指数@成交额[日期]` | 当日成交额 | — |
| `指数@涨停家数[日期]` | 当日涨停家数 | — |
| `指数@上涨家数[日期]` | 当日上涨家数 | — |
| `指数@主力资金流向[日期]` | 当日主力资金流向 | — |
| `指数@领涨股简称[日期]` | 板块内领涨股名（需"领涨股"触发） | 通鼎互联 |

**重要**：不需要在 query 中明确说"返回指数代码"，zhishu backend 始终包含这些字段。  
明确说"返回指数代码"（S9-004/005/006）也是 stable，因为 pywencai 把它理解为普通条件并忽略，照常返回。

**指数代码格式**：6位数字（88xxxx / 884xxx），末尾带 `.TI` 后缀，不是 A 股代码。

### 3. 龙头股/领涨股能不能在 sector 路由直接返回？

**部分可以（仅限 `领涨股`，不含 `龙头股`）。**

| 问法 | 结果 | 说明 |
|------|------|------|
| 今日涨幅排名前5的板块**及其领涨股** | rc=5, sector_with_index_fields | **触发 `指数@领涨股简称` 列！** 每行含一只领涨股名 |
| 今日涨停家数排名前5的板块**及其龙头股** | rc=2, sector_with_index_fields | "龙头股"不触发领涨股列；只返回板块列表 |
| 军工板块领涨股 | empty_result | 指定板块名+领涨股 → 直接失败 |
| 军工板块中今日涨幅排名前10的股票 | empty_result | must_split（二次确认） |
| 今日涨幅前5的板块，然后查询每个板块中涨幅前3股票 | empty_result | 复合问法 → 直接失败 |

#### 关键发现：`指数@领涨股简称` 列

当 query 包含 `领涨股` 时，pywencai zhishu 返回额外列：

```
指数@领涨股简称[20260507]
```

实测数据（S9-007）：

| 指数简称 | 领涨股简称 | 涨跌幅 |
|----------|-----------|--------|
| 通信线缆及配套 | **通鼎互联** | 6.91% |
| 机床工具 | **宇环数控** | 5.27% |
| 激光设备 | **大族激光** | 4.95% |
| 光纤概念 | — | — |
| 光伏加工设备 | — | — |

**限制**：
- 只返回股票名称（简称），不返回股票代码
- 只有 1 只领涨股 per 板块（不是 Top N）
- 只有 `领涨股` 能触发（`龙头股` 不能触发）
- 指定板块名称（如"军工板块领涨股"）直接失败，必须用条件筛选

### 4. 标准拆分链路

对于需要"板块内股票"的查询：

```text
Step 1 sector（推荐写法）:
  今日涨幅排名前5的板块及其领涨股
  → 返回: 板块名 + 领涨股简称（每板块1只）

Step 2 可选-名称查询（问财选A股）:
  {领涨股简称}，今日涨幅、成交额、主力净流入
  → 但简称可能重名，建议用代码查询更稳

Step 2 替代（问财选A股 条件筛选）:
  {板块名}中今日涨幅排名前N的股票
  → 已确认 S6/S8 此类失败；改用:
  {板块名}，今日涨幅大于3%的股票（走 astock 路由）
```

### 5. 哪些写法要禁止自动生成

| 写法 | 理由 |
|------|------|
| `...，上涨原因是什么` | KILLS QUERY，返回空 |
| `...，原因是什么` | 被忽略，无意义追加 |
| `龙头股`（作为 sector 内条件） | 不触发领涨股列 |
| 指定板块名 + 领涨股 | 直接失败（必须用条件筛选） |
| 板块内今日涨幅前N股票 | 直接失败 |
| 两步嵌套问法（然后查询每个板块...） | 直接失败 |

### 6. 哪些字段可展示给策略台/输入工坊

可以稳定展示的字段（sector zhishu 返回默认包含）：

```text
指数简称      → 板块名
指数@涨跌幅   → 今日涨跌幅
指数@成交额   → 今日成交额  
指数@涨停家数 → 今日涨停家数（当含此条件时）
指数@上涨家数 → 今日上涨家数（当含此条件时）
指数@主力资金流向 → 今日主力净流入（当含此条件时）
指数@领涨股简称 → 板块领涨股名（当 query 含"领涨股"时）
```

**不能展示**：
- 上涨原因文本（不存在）
- 板块内股票代码列表（不存在）
- 多只领涨股（只有1只）
