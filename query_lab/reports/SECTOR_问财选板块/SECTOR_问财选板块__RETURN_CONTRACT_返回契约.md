## 核心发现

### 1. 问财选板块的主对象是板块（sector_with_index_fields）

所有成功返回的查询均为板块列表。pywencai 通过 `zhishu` 路由返回指数简称+指数字段，
对应中文板块/概念/行业名称（如"AI应用"、"通信线缆及配套"、"小红书概念"等）。

新版 adapter（Step 0 修复后）将成功结果正确分类为 `sector_with_index_fields`，
旧版 adapter 将相同数据分类为 `sector_only`（未检测 index fields）。

**从未观察到**：
- `stock_only`（A 股代码列表）作为直接返回
- `mixed_sector_stock`（板块+股票混合）
- `sector_with_reason`（原因文本列在任何条件下均未出现）

### 2. actual_query_backend 实测

| backend | 出现场景 | 含义 |
|---------|---------|------|
| `zhishu` | 所有成功查询 | 问财通过指数维度返回板块列表 |
| `sector+zhishu_fallback` | 所有失败查询 | sector 和 zhishu 均无结果 |
| `sector` | 未观察到 | sector backend 直接返回的情况未发现 |

**重要**：`sector` 路由本身未能独立返回结果；所有成功查询实际走 `zhishu` fallback。

### 3. 哪些问法返回板块

- 基于字段+运算符的条件查询（涨幅/成交额/净流入/换手率/量比/涨停家数/上涨家数）
- 排名类查询（排名前N）
- 跨时间窗口条件组合（近20日、近60日 + 今日）
- 情绪指标（涨停家数、上涨家数）
- 含"领涨股"的条件查询（返回板块列表 + 每板块1只领涨股简称）

### 4. 哪些问法跳到股票

**无观察到**。所有查询要么返回板块，要么返回空。  
即使写"X板块中的股票"，sector 路由也是返回空，而不是返回股票。

**特例（S9-007）**：含"领涨股"可在板块行中附带1只股票简称，但返回类型仍为 `sector_with_index_fields`，不是 `stock_only`。

### 5. 哪些问法只返回文本/理由

**无观察到**。S9 明确验证：

| 原因写法 | 实际行为 |
|---------|---------|
| `上涨原因是什么` | **KILLS QUERY**：整条 query 返回空（empty_or_error） |
| `原因是什么` | **reason_query_ignored**：pywencai 忽略，返回正常板块列表，无原因列 |
| `资金流入原因是什么` | **reason_query_ignored**：同上 |

结论：原因文本字段在 sector 路由中**不存在**，严禁自动生成"原因是什么"类追问。

### 6. 指数字段默认返回

zhishu backend 每行始终包含（无需在 query 中指定）：

| 字段 | 含义 |
|------|------|
| `指数代码` | 88xxxx/884xxx 格式，末尾带 `.TI`，**不是 A 股代码** |
| `指数简称` | 板块名称（中文） |
| `指数@涨跌幅:前复权[日期]` | 当日涨跌幅 |
| `指数@成交额[日期]` | 当日成交额（当 query 含成交额时） |
| `指数@涨停家数[日期]` | 当日涨停家数（当 query 含涨停家数时） |
| `指数@主力资金流向[日期]` | 当日主力净流入（当 query 含主力净流入时） |
| `指数@领涨股简称[日期]` | 板块领涨股名（当 query 含"领涨股"时，每板块1只） |

### 7. 领涨股字段说明（S9-007 实测）

| 板块名 | 领涨股简称 | 涨跌幅 |
|--------|-----------|--------|
| 通信线缆及配套 | 通鼎互联 | 6.91% |
| 机床工具 | 宇环数控 | 5.27% |
| 激光设备 | 大族激光 | 4.95% |

**限制**：
- 触发词：仅 `领涨股`，`龙头股` 不触发
- 数量：每板块仅1只
- 内容：只有股票简称，没有股票代码
- 指定板块名 + 领涨股（如"军工板块领涨股"）→ 直接失败

## 按返回类型的 pipeline 接法

### sector_only / sector_with_index_fields → Phase B

两种类型接法相同（zhishu 始终返回指数字段；分类标签取决于 adapter 版本）。

```text
sector 返回"AI应用板块"
→ 下一步 astock:
  "AI应用板块中，今日收盘价站上5日均线，主力净流入大于0的股票"
```

注意：Phase B 的 astock 查询必须把板块名作为条件前缀，不是 sector 再次查询。

### sector_with_index_fields + 领涨股 → 含领涨股名的接法

```text
sector 返回 [("通信线缆及配套", "通鼎互联"), ("机床工具", "宇环数控"), ...]
→ 选项 A：用领涨股名直接查 astock:
    "通鼎互联，今日涨幅、主力净流入"
→ 选项 B：用板块名接 Phase B（忽略领涨股名）:
    "通信线缆及配套板块，今日涨幅大于3%的股票"
```

### empty_or_error → failed

记录失败原因，不进入 pipeline。可尝试简化条件或拆分为两步。

### stock_only（未观察到，理论处理）

若未来某问法触发 stock_only：  
直接进入本地技能（kline/smc/wave/landmine），**不可**再送回问财选A股。

### mixed_sector_stock（未观察到，理论处理）

拆开处理：板块部分进 Phase B，股票部分进本地技能。标记为 review，不自动运行完整 pipeline。

## 返回列结构

实测列结构（zhishu backend 返回）：

```text
指数代码 | 指数简称 | 指数@涨跌幅:前复权[20260507] | 指数@成交额[20260507] | 指数@同花顺行业指数 | market_code | code
```

含"领涨股"时额外出现：
```text
指数@领涨股简称[20260507]
```

- `指数简称` = 板块名称（中文）
- `指数代码` = 8开头的6位数（88xxxx/884xxx），**不是 A 股代码**
- `指数@领涨股简称` = 每板块一只领涨股简称（仅当 query 含"领涨股"时出现）
- 提取时必须用 `指数简称` 列，不要误读 `code` 列为股票代码

## 禁止生成的写法（S9 新增）

| 写法 | 行为 | 严重程度 |
|------|------|---------|
| `...，上涨原因是什么` | KILLS QUERY，整条返回空 | **严禁** |
| `...，原因是什么` | reason_query_ignored，无意义 | 禁止 |
| `龙头股`（sector 条件） | 不触发领涨股列，仅返回板块 | 禁止（用`领涨股`代替） |
| `指定板块名+领涨股` | 直接失败（如"军工板块领涨股"） | 严禁 |
| 两步嵌套问法 | 直接失败（如"TOP5板块，然后查每板块TOP3股"） | 严禁 |
